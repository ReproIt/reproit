# SDK support

Twenty SDK directories ship in this repository. Every one of them is fully
supported. There is no core tier, no community tier, and no unmaintained tier:
if an SDK is in ReproIt then its suite runs on every push and a failure fails
the build.

This file replaces `docs/sdk-tiers.md`. That file said three different things
about what an SDK promised, and nine SDKs sat in the bucket that promised
nothing. The product copy promises every bug is reproducible, and a support tier
is exactly the hedge that copy must never carry.

The declaration lives in exactly one place, `sdk/INVENTORY.json`.
`sdk/check-inventory.py` fails when it drifts from reality, including when a
declared gate string is absent from `.github/workflows/ci.yml`, and including
when any job sets `continue-on-error: true`, which is a support tier spelled in
YAML.

## What "fully supported" is a mechanism for

| claim | mechanism |
| --- | --- |
| the SDK's own suite runs on every push | a declared, blocking `gate` in `ci.yml`, checked by `check-inventory.py` |
| the WHOLE suite runs, not a subset | the `runs` sentence per SDK, plus the audit below |
| the shared behavioral vectors execute | `sdk/check-behavior-coverage.py` |
| a defect blocks a release | no job is advisory; `check-inventory.py` refuses `continue-on-error: true` |

## What promoting every SDK actually cost

Promoting a tier does not make an SDK good, so every suite was run. What that
found:

**Seven SDKs had no mention in `ci.yml` at all.** `reproit-backend-java`,
`reproit-backend-dotnet`, `reproit-backend-rb`, `reproit-backend-php`,
`reproit-tauri`, `reproit-recorder-node`, and `reproit-tui-rs` (the last one
gated only by accident of being a workspace member, which `cargo test
--workspace` picked up without ever naming it). All seven pass. Each now has a
gate that names it.

**Four more ran only part of their suite.** `reproit-linux` ran four of seven
files; `reproit-tui-py` ran two of five; `reproit-tui-ts` ran two of four;
`reproit_flutter` ran the package tests but not the six example fixture suites,
which live in a separate pub package that `flutter test` in the SDK root never
reaches. `reproit-backend-node` and `reproit-backend-py` each skipped their
`e2e` file. `reproit-android` compiled nine of its ten JUnit classes and left
`CapsuleSpoolTest` out. All of these now run, and all of them pass.

**The Ruby SDK's suite is not process-shareable.** `test/replay_test.rb` sets
`REPROIT_REPLAY` in the process environment at load time and never unsets it, so
running the six files in one interpreter leaves every later file replaying
against a spent capture: 2 failures and 4 errors, none of them real defects in
the code under test. CI runs one `ruby` process per file, which is honest about
the SDK's process-global state rather than hiding it. This is a real wart and it
is written down here rather than papered over.

**The Tauri plugin's generated permission surface had drifted.** Its Rust half
is a separate cargo workspace, so no root workspace job compiled it, and its
build script regenerates `permissions/`. Both
`permissions/autogenerated/reference.md` and `permissions/schemas/schema.json`
still carried a description that `permissions/default.toml` had moved on from.
Building it regenerated them. `ci.yml` now compiles the crate under
`clippy -D warnings` and then requires `git diff --exit-code` over
`permissions/`, so the artifacts cannot drift again.

## Changing this

Add an SDK directory and `check-inventory.py` fails until `INVENTORY.json`
declares it and `ci.yml` contains the gate it declares. That is the intended
order: the promise cannot exist before the mechanism.
