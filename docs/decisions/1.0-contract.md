# Repro It 1.0 compatibility contract

Repro It 1.0 freezes the meaning of a reproduction, not the mechanisms used to
obtain one. A 1.x release may replace runners, storage, search strategies, and
presentation, but it must preserve the contracts below.

## Product invariants

1. Only the exact captured failure identity is a reproduction. A different
   failure is never equivalent evidence.
2. The Repro It SDK is the production capture authority for replayable dependency
   exchanges. Imported diagnostics may add context but cannot make an occurrence
   executable.
3. Missing, malformed, ambiguous, stale, or unsupported evidence fails closed.
   It never becomes a clean run or a confirmed bug.
4. Evidence cannot grant execution authority. Build, reset, launch, trigger, and
   cleanup mechanisms come from a trusted checkout, built-in adapter,
   organization policy, or explicit local approval.
5. Cloud never executes customer applications and does not require customer
   source code.
6. Reproduced, not reproduced, different failure, flaky, stale, inconclusive,
   unsupported, and infrastructure failure retain distinct meanings.
7. Guard refresh may re-record dependency exchanges only after exact
   confirmation. It never changes the inbound trigger or failure oracle.
8. Stable occurrence, finding, artifact, graph, and guard identities do not
   change when implementation details or checkout locations change.
9. Exportable evidence is classified and redacted before it crosses the capture
   boundary. Restricted values do not become exportable through normalization.
10. Every advertised SDK and platform is backed by its declared blocking suite
    and applicable native evidence.

## Stable public surfaces

The public command loop, machine-readable result fields, exit-code meanings,
wire schema versions, persisted guard formats, capsule version 2, and content
identity algorithms are compatibility surfaces. A change that alters their
meaning requires a new explicitly dispatched schema version or a future major
release.

All artifact schema versions emitted by a supported 1.x SDK remain readable for
the rest of the 1.x line. New readers normalize frozen version-specific values
into the current internal model. Existing wire structures are never widened by
silently adding fields, and unknown versions fail with a named repair.

## Replaceable mechanisms

These may change behind the stable surfaces:

- Detector, search, confirmation, and minimization implementations
- Runner, device, simulator, VM, and container mechanisms
- Cloud database and object-store implementations behind verified migrations
- Dashboard presentation and hidden specialist commands
- CI providers and checkout-owned execution-provider implementations
- Platform acquisition mechanisms that emit the same bounded evidence contract

## Extension rule

Every future target enters the existing pipeline:

```text
capture -> normalize -> evaluate -> occurrence -> readiness -> trusted plan
        -> execute -> receipt -> exact verdict -> guard
```

A target may add capture, environment, reset, build, launch, readiness, trigger,
observation, and cleanup adapters. It may not redefine evidence authority,
failure identity, verdict aggregation, Cloud tenancy, or guard persistence.

## Fix scope

An occurrence is one exact captured failure. A bug bucket groups related
occurrences. Environment dimensions remain attached to occurrences unless
minimization proves one is required by the guard.

Repro It distinguishes:

- Fixed for one occurrence
- Fixed across all observed required environments
- Resolved in production after bounded post-fix evidence

One clean replay never proves that a bug is fixed in every environment.

## Enforcement

Architecture, protocol, compatibility, release, dogfood, and native-evidence
gates enforce this document. A public promise without an executable gate is a
release blocker, not documentation debt.
